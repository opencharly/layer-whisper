# 2026.319.1437 — fix(whisper): the skill node stops carrying a second, drifted description

## Summary

The `whisper-skill:` node in `charly.yml` carried an inline `description:` that had **drifted** from
the file's frontmatter — three sentences on the node, two in the file:

| side | text |
|---|---|
| node (`charly.yml`) | "OpenAI Whisper speech-to-text, served as an OpenAI-compatible ASR endpoint. Use when working with the whisper candy, its STT service, or wiring a speech-to-text backend into another pod." |
| file (`.agents/skills/whisper/SKILL.md`) | "OpenAI Whisper local speech-to-text. Use when working with the whisper candy." |

The marketplace generator hard-errors on exactly that disagreement:

```
charly marketplace: skill "whisper": the node's inline `description:` and its file's frontmatter disagree
```

which stops the whole corpus build (`opencharly/marketplace#613`).

The rule in the generator (`fillSkillFromFile`) is: *if* the node declares a `description:` it must
EQUAL the file's frontmatter; if the node declares none, the file wins. The authored-content
contract says the same thing from the other side — the node carries **routing only**
(`name`/`family`/`owner`/`triggers`) and the prose lives in the file.

| file | change |
|---|---|
| `charly.yml` | the node's inline `description:` is removed, replaced by a comment recording why (routing only) |
| `.agents/skills/whisper/SKILL.md` | its frontmatter takes over the richer prose, so the published text keeps the detail instead of losing it |

### The discriminating proof: the generator, over the old shape and the new one

The instrument is the real generator, run over a throwaway project whose `candy/whisper/charly.yml`
and `.agents/skills/whisper/SKILL.md` are copied **from `origin/main`** (old) and **from this
branch** (new). The only difference between the two runs is this diff:

```
$ cd /tmp/rdd-wh-old2 && charly marketplace generate --root . --out /tmp/rdd-wh-old2
charly marketplace: skill "whisper": the node's inline `description:` and its file's frontmatter disagree
EXIT=1
```

```
$ cd /tmp/rdd-wh-new2 && charly marketplace generate --root . --out /tmp/rdd-wh-new2
EXIT=0
```

**RCA of my first attempt at this probe (it passed both ways, and I said so).** My first probe put
the skill node in the project's **root** `charly.yml` and got `EXIT=0` on both sides. The cause: the
generator walks a LOCAL project's `candy/` and `box/` directories — a root manifest is read only for
a *fetched remote* repo (`candywalk`'s pass 1 vs pass 2). The real corpus reads `layer-whisper` as a
remote repo, so its root manifest **is** walked there; my first probe had the node somewhere the
generator never looks. Moving the node under `candy/whisper/` made the instrument discriminate, and
the pair above is the result. The missed control was mine: I did not check that the fixture reached
the code path I was testing.
