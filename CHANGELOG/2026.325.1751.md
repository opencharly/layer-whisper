# 2026.325.1751 — fix(whisper): pin HOME for a bound deployment

## Summary

Pins `HOME: /home/user` so a **bound** whisper deployment reads and writes the image user's home —
where the model store is mounted — instead of `/root` (opencharly/layer-whisper#13).

**Why it is needed.** A host-owned bind makes charly run the container as root under its keep-id
mapping, where the runtime `HOME` is `/root`. The candy's model directory is derived from `HOME`
(`~/.cache/whisper`), and the deployment binds the shared store at the image user's home. Without
the pin the process resolves `/root/.cache/whisper`, re-downloads the checkpoint into the container
layer, and the bind is silently dead — the same defect already fixed in pod-openwebui, pod-comfyui
and pod-ollama.

```diff
         env:
+            HOME: "/home/user"
             WHISPER_MODEL: "base"
             …
```

**The structure around the change, shown rather than inferred** (the diff hunk could not show the
enclosing keys):

```yaml
        env_provide:                                   # NOT an env map — a provide
            WHISPER_BASE_URL: "http://{{.ContainerName}}:9000/v1"
        port:
            - 9000
        env:                                           # the ONE env map of this candy
            HOME: "/home/user"                         # ← the change
        volume:
            - name: whisper-models
              path: "~/.cache/whisper"
        service:
            - name: whisper-asr
```

`WHISPER_BASE_URL` sits under `env_provide:` (its provider contract), and the candy carries exactly
one `env:` key; `HOME` was added inside it. No duplicate key exists, and `charly box validate` is
green on this tree.

`HOME=/home/user` and the model cache resolving under it.
