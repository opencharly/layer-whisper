# 2026.290.1729 — fix(whisper): advance the layer-cuda pin past the Arch gpgcheck fix

## Summary

One link of a transitive pin cascade, and the link that reddens every bed in the CachyOS GPU chain.

`charly.yml` pinned `layer-cuda:v2026.274.0643`. That cuda candy in turn pins `layer-nvidia:v2026.271.1817` — the pre-`#12` tag whose gpgcheck step asserts `stdout: gpgcheck=1` against `/etc/dnf/repos.override.d/99-config_manager.repo`, which cannot exist on an Arch-family arm. `layer-nvidia#12` moved that assertion into the command so the Arch arm skips honestly, so a consumer must pin a `layer-cuda` whose own nvidia pin is that fix.

Because a candy check runs in the **check-image phase of every box that composes it**, this one stale transitive pin fails every bed in the tree. Measured on the GPU-free bed `check-strata-pod`: **39 of 40 steps pass**, and the single failure is this probe.

This advances `layer-cuda` to `v2026.290.1513` (layer-cuda#16's merge tag; its own nvidia pin is `054aa7702ebe`, layer-nvidia#12).
